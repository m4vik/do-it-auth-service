# Результаты проверки Auth Service

Дата: 16 октября 2026 года.
Основная backend-версия: `071b4a5`, вошедшая в тег `v1.0.0`. Результаты её проверки приведены ниже. Последующее добавление тестовой страницы описано в разделе «Тестовая панель».

## Сборка и зависимости

- `dotnet build --no-restore`: успешно, 0 ошибок и 0 предупреждений.
- `dotnet format --verify-no-changes --no-restore`: успешно.
- `dotnet ef migrations has-pending-model-changes --project src/AuthService`: модель соответствует миграции.
- `dotnet list package --vulnerable --include-transitive`: известных уязвимых NuGet-пакетов не найдено по доступным источникам на дату проверки. Это проверка зависимостей, а не независимый аудит безопасности.

## Автоматические тесты

- Локальный .NET SDK + отдельные PostgreSQL/Redis: **24/24** успешно.
- Чистый клон, тесты внутри Docker: **24/24 успешно**.
- Тесты используют настоящие PostgreSQL и Redis, отдельную временную БД и уникальный префикс ключей Redis. Моки БД и SQLite не используются.

Проверены нормализация email/телефона, уникальность при параллельной регистрации,
хеширование пароля, вход до подтверждения контакта, оба полных сценария,
включение/выключение 2FA, отсутствие токенов до второго фактора, отмена устаревших
challenge, ограничение попыток, TTL и замена кодов, защита от повторного применения,
разделение Access/Refresh, истечение JWT и сессии, конкурентные refresh,
refresh/logout, подтверждение контакта и второй фактор.

Дополнительный регрессионный тест воспроизводит реальный отказ подключения БД через
HTTP: ошибка провайдера, обёрнутая EF Core, преобразуется в `503 storage_unavailable`.

## HTTP-проверка запущенного Docker API

**38/38 проверок успешно**, отдельно от WebApplicationFactory:

- Email и телефон: регистрация, активный неподтверждённый профиль, вход без подтверждения.
- Получение настоящего демонстрационного кода из логов соответствующей заглушки.
- Подтверждение контакта, включение 2FA, отзыв прежней сессии.
- Login возвращает challenge без основной пары токенов; код завершает вход.
- Выключение 2FA, ротация refresh, logout, отклонение отозванных Access и Refresh.
- После перезапуска API и Redis сохраняются действующая сессия и подтверждение контакта; отозванная сессия не восстанавливается.
- При остановленном Redis вход возвращает 503.
- При остановленном PostgreSQL защищённый запрос возвращает 503.
- После возврата хранилищ API восстанавливает обслуживание.

- Финальная проверка чистого клона: **успешно**. Новая БД, генерация ключей и миграции выполнены автоматически; HTTP-регистрация, вход, профиль и logout проверены. Все 24 теста прошли внутри Docker; Git-состояние клона осталось чистым. Проверочные контейнеры и volumes удалены, основное приложение восстановлено.

## Тестовая панель (v1.1.0)

Добавлена по отдельной просьбе пользователя после реализации backend. Это статические
HTML/CSS/JavaScript-файлы в wwwroot, которые вызывает ASP.NET Core; отдельного frontend-сервера,
новых бизнес-эндпоинтов и дополнительных зависимостей нет. API работает по прежнему контракту.

Проверка выполнена в отдельном Docker Compose-проекте `do-it-auth-ui-check` на localhost:18081,
с отдельными PostgreSQL и Redis; основной пользовательский запуск на 8080 не перезапускался.

- Сборка .NET и проверка форматирования: успешно, без ошибок и предупреждений сборки.
- Проверка синтаксиса JavaScript (`node --check`): успешно.
- Все **24 backend-теста** в Docker: успешно.
- В браузере: регистрация по email, вход, профиль, получение и ввод кода контакта.
- В браузере: включение 2FA, повторный вход с отдельным вторым шагом, ротация токенов, выключение 2FA и выход.
- В браузере: выбор телефона, регистрация, вход, профиль и подтверждение через SMS-заглушку.
- Ошибка повторной регистрации отображается как HTTP 409, после неё интерфейс остаётся рабочим.
- Токены скрыты в ответе по умолчанию; перезагрузка вкладки очищает локальное состояние входа.
- Внешний вид проверен скриншотом, ошибок JavaScript после перезагрузки не обнаружено.

Коды по-прежнему читаются из логов Docker и вводятся вручную. Доступа к кодам через страницу или отдельный debug API нет.
